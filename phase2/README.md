# AR Troubleshooting Companion - Phase 2

A runnable local manual-ingestion and admin-review prototype for the Breville Bambino Plus BES500. Built from the supplied project brief and Phase 1 proposal on 22 October 2026.

**Delivered:** PDF text/table extraction, rendered vector diagrams and reference crops, strict procedure JSON schema, three LLM-generated source-linked drafts, real local MiniLM embeddings, SQLite storage, an editable admin page, versioned review/publication, a CLI and tested HTTP upload flow.

**Completion boundary:** The bundled demonstration is working and tested. Its LLM response was generated by Codex during implementation, then frozen for deterministic replay against the exact manual hash. Replay does not make a new LLM call. A Gemini API adapter supports fresh generation on other selectable-text PDFs; its contract is mock-tested but a live API call has not been verified because no provider credentials were supplied. No human approval, mentor sign-off or physical repair is claimed. All delivered procedures are drafts.

For the recommended script-policy-safe setup, follow the repository root README.

## Run on Windows

Use 64-bit Python 3.12 and Poppler (`pdftoppm`) on PATH. The scripts also recognize the Codex bundled runtime on this computer. From this directory:

```powershell
.\Setup.ps1
.\Start-Demo.ps1
```

Setup creates `.venv`, installs the tested package versions, downloads the official public manual, checks its identity during ingestion, and downloads a pinned MiniLM model (about 90 MB). Open http://127.0.0.1:8765. Do not expose this local prototype to a network; it has no production authentication or tenant isolation. No API key is needed for the bundled demo.

If PowerShell policy blocks scripts, use the equivalent commands below with your Python executable; do not disable organizational protections.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m ar_companion.cli ingest path\to\BES500_USCM_IB_T23_LR.pdf --appliance-id breville-bes500
.\.venv\Scripts\python.exe -m uvicorn ar_companion.app:app --host 127.0.0.1 --port 8765
```

Linux/macOS: use a virtual environment, install `requirements.txt` and Poppler, and run the same Python modules. Windows is the tested platform.

## Demo 2 walkthrough

1. Select the official BES500 PDF and keep appliance ID `breville-bes500` and bundled demo mode. Click **Extract & create drafts**. A repeated upload loads the saved record without overwriting edits.
2. Inspect P01 (no flow), P05 (portafilter-edge leakage), and P10 (water leakage). Compare each remedy with its source-page image and each part with the component/accessory diagram. Source pages are 1-based PDF pages, matching printed pages for this manual.
3. Edit a physical instruction, or expand the full JSON editor to change causes, parts, evidence regions or references. **Save draft** validates the entire record, refreshes its embedding and increments the version.
4. Use the source buttons and reference images for review. Only a real reviewer should complete the five attestations and enter their name to publish. Do not use publication merely to make the dashboard count green.
5. Try `Coffee leaks around the filter holder`. Admin preview includes drafts. Uncheck it to confirm that live retrieval returns no procedure before publication. Scores are cosine similarities, not probabilities. This Phase 2 screen does not execute repair steps.
6. Export the JSON for the next implementation phase. Editing a published procedure returns it to draft; the previous immutable release remains in the audit database and is no longer offered through live search.

## Fresh LLM generation for a new PDF

Configure `GEMINI_API_KEY` and `GEMINI_MODEL` in the server's local environment through your normal secret-management process; do not commit them or enter them in the UI. The model must support `generateContent` structured JSON output. No default model name is guessed. Selecting Gemini transmits the selected extracted text to Google; the browser labels this explicitly.

```powershell
.\.venv\Scripts\python.exe -m ar_companion.cli ingest .\new-manual.pdf --appliance-id exact-model-id --provider gemini --pages 2-8,19-24
```

This is the one-command new-PDF pipeline after environment setup. It extracts source material, requests structured drafts, validates them, renders references, computes embeddings, and stores the result. Omit `--pages` to process all pages for an unknown manual. At most 150 pages / 25 MB / 150,000 selected source characters are accepted; exceeding a limit produces an explicit error. Scan-only PDFs require OCR first and fail closed. Page images are available to the reviewer; the current API adapter sends text, not images. It cannot automatically name parts that exist only in unlabeled diagrams.

The BES500 default explicitly processes pages 2-7 and 19-21: safety, parts, accessories and English troubleshooting. It does not claim to ingest all three languages. For the demo, other manual bytes or appliance IDs are rejected instead of receiving inappropriate cached procedures. Fresh Gemini generation should use a fresh `--data-dir` if the same manual is already ingested, since duplicate uploads intentionally preserve existing work.

## Evidence and data layout

```text
ar_companion/       extraction, schema, provider adapter, embeddings, persistence, API, CLI
static/             responsive admin page, CSS and JavaScript; no CDN dependencies
sample/             frozen drafts, schema, vectors, query fixtures and extracted evidence snapshot
docs/               prompt, architecture, evaluation results, test report and limitations
tests/              behavioral tests and reproducible retrieval evaluation
data/               created at runtime, excluded from version control
  companion.sqlite3 procedures, vectors, immutable releases and audit events
  manuals/<sha>/    original PDF, extraction JSON, page PNGs, crops and generation record
  models/           pinned ONNX model, tokenizer and SHA-256 manifest
```

The extraction JSON contains page text, word coordinates, table candidates, vector/raster counts and image filenames. Multirow PDF tables remain review evidence, not assumed-perfect relational rows. Vector diagrams are rendered before cropping. BES500 crops are source-specific reference illustrations, not detected part masks.

`sample/extracted/` contains the actual nine-page extraction result and rendered evidence from the verified run. `sample/embeddings.json` contains the generated vectors, and `sample/embedding-model.json` records the model-file hashes. These snapshots let you inspect the completed ingestion without installing the app. Setup still re-extracts the official PDF rather than trusting the snapshots as a new upload.

Procedure evidence uses normalized `[left, top, right, bottom]` regions on the source page. Physical steps require manual evidence; the fixed unplug/cool steps cite a separate project policy. Cause IDs keep alternatives separate. Reference filenames must belong to the same extracted manual. Schema validation checks structure and references; a human must establish semantic correctness.

## Validation

```powershell
$env:AR_TEST_SOURCE = (Resolve-Path data).Path
$env:AR_MODEL_CACHE = (Resolve-Path data\models).Path
.\.venv\Scripts\python.exe -m pytest tests\test_phase2.py -q
.\.venv\Scripts\python.exe tests\evaluate_retrieval.py --data-dir data --model-cache data\models --output docs\retrieval-results.json
```

Automated tests operate on temporary copies and do not publish the user's drafts. Initial results: **29 tests passed**, **9/10 positive top-1 rankings**, and **4/6 unsupported queries below the exploratory 0.38 threshold**. The two unsupported false candidates and the one misranking are retained in `docs/retrieval-results.json`. This is a small, author-created smoke set, not an independent benchmark or proof of safe autonomous matching. UI checks verified draft saving, version increment, reference viewing and retrieval.
